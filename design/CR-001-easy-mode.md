# CR-001 — โหมดง่าย (Easy Mode) แยกจากโครง terminal

- **สถานะ:** อนุมัติแล้ว (THP "Go" 2026-11-25)
- **วันที่:** 2026-11-25
- **อ้างอิง:** `design/ux-review-2026-11-25/UX-REVIEW.md` (UX-01, UX-02, UX-03, UX-04, UX-07, UX-12, UX-14, UX-16) · `docs/dev/PRODUCT.md` · brain `decisions/decision-premium-radar-ux-two-modes`
- **แตะ:** `design/DESIGN.md` §1.2 ข้อ 1–3 และ §4 (Structure Freeze)

## 1. ขอเปลี่ยนอะไร

เพิ่ม **โหมดง่าย** เป็นโครงหน้าจอชุดที่สอง เป็นค่าเริ่มต้นสำหรับผู้ใช้ใหม่ ส่วนโครง terminal 4 คอลัมน์เดิมยังอยู่ครบในชื่อ **โหมดละเอียด** และ freeze เหมือนเดิมทุกข้อ

| | โหมดง่าย (ใหม่ · ค่าเริ่มต้น) | โหมดละเอียด (เดิม) |
|---|---|---|
| โครง | 1 จอ 1 คำถาม คอลัมน์เดียวตรงกลาง ไม่มี icon rail / แผงซ้าย / แผงขวา | 4 คอลัมน์ตาม §4 ไม่เปลี่ยน |
| เส้นทาง | ① หุ้นที่ฉันสนใจ → ② agent เสนอ → ③ การ์ด 5 คำถาม → ④ ก่อนตัดสินใจ | หน้า Home / Market / Options / Lab / Watchlists / Portfolio |
| ภาษา | ไม่มีศัพท์ option ในข้อความหลัก | ศัพท์เทคนิคได้ |
| Agent | อยู่กลางจอ เป็นฝ่ายเสนอก่อน | ปุ่มลอยแบบเดิม |
| ตัวอักษร | ข้อความหลัก ≥ 15–16px ตัวเลขสำคัญ ≥ 24px | ตาม §3 |
| ข้อมูล / สูตร | `radar-core` ชุดเดียวกัน | ชุดเดียวกัน |

สลับโหมดได้จากปุ่มเดียวที่มุมบนขวา (appbar) และจำค่าที่เลือกไว้

## 2. สิ่งที่ไม่เปลี่ยน

- โหมดละเอียด: โครง §4, ลำดับ §1.2, component contract §5 และ interaction §6 ทั้งหมด
- Design tokens §2 (สี charcoal, electric blue สำหรับ selection, เขียว/แดง/เหลืองเชิงการเงิน) ใช้ร่วมกันทั้งสองโหมด
- ป้ายแหล่งข้อมูล LIVE / API / DEMO / ราคาปิด ต้องมีในทั้งสองโหมด
- สูตรการเงินและเกรด A/B/C ไม่เปลี่ยน

## 3. ข้อความที่จะแก้ใน DESIGN.md เมื่ออนุมัติ

- §1.2 เพิ่มย่อหน้า: "ข้อ 1–3 ผูกกับ **โหมดละเอียด** โหมดง่ายมีสัญญาโครงของตัวเองใน §4.7 (CR-001)"
- §4 เพิ่ม §4.7 Easy Mode shell: appbar 43px คงเดิม + พื้นที่เนื้อหาคอลัมน์เดียว (กว้างสูงสุด ~760px อยู่กลาง) + statusbar 25px คงเดิม
- §5 เพิ่ม component: การ์ด 5 คำถาม, การ์ดข้อเสนอของ agent, การ์ดหุ้นที่สนใจ (ป้าย อยากถือ / ไม่อยากถือ), checklist ก่อนตัดสินใจ

## 4. ลำดับงานหลังอนุมัติ

1. ทำ prototype HTML แบบคลิกได้ของโหมดง่ายผ่าน impeccable skill (ยังไม่แตะแอป)
2. ตรวจ prototype กับ 3 งานใน UX-REVIEW §8 (ต้องตอบได้จากหน้าจอโหมดง่ายเท่านั้น)
3. แก้ DESIGN.md ตามข้อ 3 แล้วจึงวาง spec การ implement

## 5. ความเสี่ยง

- ต้องดูแล 2 ชุดหน้าจอ → ลดด้วยการใช้ข้อมูล, สูตร และ token ชุดเดียว แยกเฉพาะชั้นการแสดงผล
- การ์ด 5 คำถามต้องใช้ข้อความที่ถูกต้องทางการเงิน → ตัวเลขทุกตัวมาจาก `radar-core` agent อธิบายได้แต่ห้ามสร้างตัวเลขเอง (PRODUCT.md หลักข้อ 1)
- ข้อ "ทำไมช่วงนี้น่าทำ" ต้องอิงสัญญาณจากข้อมูลจริง สัญญาณ OI ใหม่ยังต้องรอพิสูจน์ใน Option Lab (W5) → ระยะแรกใช้เฉพาะสัญญาณที่มีอยู่แล้ว เช่น IV เทียบกับความผันผวนจริง

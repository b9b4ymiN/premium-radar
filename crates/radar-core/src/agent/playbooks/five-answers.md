# อธิบายไอเดียด้วยคำถาม 5 ข้อ

คู่มือสำหรับ AI agent — วิธีอธิบาย "ไอเดียขาย option ตัวใดตัวหนึ่ง" ให้ผู้ใช้ตัดสินใจเองได้
โดยไม่ต้องรู้ศัพท์ option เลย ใช้โครง 5 คำถามเดียวกับหน้าจอ Easy Mode

## กฎเหล็กก่อนเริ่ม

- ตัวเลขทุกตัวต้องมาจาก tool เท่านั้น ห้ามคำนวณเองเด็ดขาด
  (แม้คิดว่าคำนวณง่าย เช่น คูณ 100) ถ้าผู้ใช้อยากเห็นตัวเลขในสถานการณ์ใหม่
  ให้เรียก tool คำนวณให้ เช่น `what_if` ถ้ายังไม่มี tool ที่ตอบได้
  ให้บอกตรงๆ ว่า "ยังคำนวณให้ไม่ได้" ห้ามเดาตัวเลขขึ้นมาเอง
- ห้ามบอกให้ผู้ใช้สั่งซื้อขาย แอปยังส่งคำสั่งซื้อขายไม่ได้
  หน้าที่เราคืออธิบายให้เข้าใจ ไม่ใช่กดสั่งแทน
- ถ้ายังไม่รู้ว่าผู้ใช้สนใจสัญญาไหน ให้เรียก `find_ideas` หาไอเดียก่อน
  แล้วค่อยอธิบายด้วยโครง 5 ข้อนี้

## คำถามที่ 1 — ได้เงินเท่าไร

บอกเงินที่จะได้รับเข้าบัญชีทันที และเป็นของผู้ใช้ไม่ว่าจะเกิดอะไรขึ้น

- ตัวเลขจาก tool: `premium_usd` (เงินที่ได้รับตอนนี้ ต่อ 1 สัญญา)
- เทียบให้เห็นภาพ: คิดเป็นกี่เปอร์เซ็นต์ของเงินที่ต้องกันไว้
  ใช้ `period_pct` (ต่อรอบจนสัญญาหมดอายุ) หรือ `annual_pct` (เทียบเป็นรายปี)
  ที่ `find_ideas` ส่งมาเท่านั้น
- ห้ามพูดว่า "ได้เงินฟรี" — เงินก้อนนี้คือสิ่งแลกกับคำมั่นในข้อ 2 เสมอ

## คำถามที่ 2 — แลกกับอะไร

อธิบายคำมั่นที่ผู้ใช้ให้ไป ด้วยคำง่ายๆ ไม่ใช้ศัพท์ option

- ขาย put = สัญญาว่า "ถ้าหุ้นปิดต่ำกว่าราคาที่กำหนด ผมจะซื้อหุ้น 100 หุ้นในราคานั้น"
- ราคาที่กำหนดมาจาก tool: `strike` (ดูว่าต่ำกว่าราคาหุ้นวันนี้กี่เปอร์เซ็นต์ด้วย `below_spot_pct`)
- เงินที่ต้องกันไว้จนสัญญาจบ มาจาก tool: `cash_needed_usd` (เงินที่เตรียมไว้สำหรับสัญญานี้)
- บอกวันหมดอายุด้วย: `expiry` และ `days` (อีกกี่วัน)
- ราคาหุ้นต่ำสุดที่ยังไม่ขาดทุน: `breakeven` (จุดคุ้มทุน)

## คำถามที่ 3 — โอกาสแค่ไหน

บอกโอกาสแต่ละทางเป็นเปอร์เซ็นต์ โดยย้ำว่าเป็นผลจากสูตรคำนวณ ไม่ใช่คำทำนาย

- โอกาสต้องซื้อหุ้น (ถูก assign): `assign_pct` จาก `find_ideas`
  อธิบายว่า "โอกาสไม่ต้องซื้อ" คือส่วนที่เหลือจาก 100% — ห้ามเรียกชื่อฟิลด์ที่ tool ไม่ได้ส่ง
- ถ้าอยากได้โอกาสเพิ่มจากตัวเลขระดับสัญญา ให้เรียก `contract_detail`
  แล้วใช้ชื่อฟิลด์จริงที่มันส่งมา เช่น `pop_pct` (โอกาสได้เงินเต็ม) และ `p_itm_pct` (โอกาสต้องซื้อหุ้น) เท่านั้น
- ถ้าผู้ใช้อยากเห็นภาพว่า "ถ้าราคาหุ้นเป็น X จะเป็นอย่างไร" ให้เรียก `what_if`
- ห้ามเรียกโอกาสเหล่านี้ว่า "การันตี" หรือ "แน่นอน"

## คำถามที่ 4 — ทำไมช่วงนี้น่าทำ

เหตุผลต้องมาจากข้อมูลจริงของช่วงเวลานี้ ไม่ใช่ความเห็นส่วนตัว

- ใช้ประโยคเหตุผล "ทำไมช่วงนี้" (why-now) ที่ `find_ideas` ส่งมา
  หรือข้อความ `text_th` ที่ tool แนบมากับตัวเลขชุดนั้น
- ถ้าอ้างถึงความผันผวน ให้ใช้ตัวเลขจาก tool เช่น iv_pct เทียบ realized_30d_pct
- ถ้า tool บอกว่ายังไม่มีข้อมูลพอ ให้บอกผู้ใช้ตรงๆ ว่า "ยังไม่มีข้อมูลพอจะบอกได้"

## คำถามที่ 5 — แย่สุดคืออะไร

ต้องตอบเป็น "จำนวนเงิน" ผูกกับเหตุการณ์ที่เข้าใจง่าย เสมอ

- กรณีหุ้นร่วง 30% ใช้ตัวเลขจาก tool: `worst_30_usd`
- ขาดทุนสูงสุดในทางทฤษฎี (ถ้าหุ้นเหลือศูนย์): `max_loss_usd`
- ห้ามตอบแบบลดความสำคัญ เช่น "ไม่ต้องห่วง เรื่องนี้แทบไม่เกิด" —
  หน้าที่ของข้อนี้คือทำให้ผู้ใช้เห็นความเสี่ยงเต็มๆ ก่อนตัดสินใจ

## ปิดท้ายทุกครั้ง

จบคำตอบด้วยการถามว่าผู้ใช้อยากเจาะดูไอเดียไหนต่อ เช่น
"อยากดูตัวไหนต่อ หรืออยากถามอะไรเพิ่มเกี่ยวกับตัวนี้"
เพื่อให้การคุยต่อเนื่อง และผู้ใช้เป็นคนเลือกเองเสมอ

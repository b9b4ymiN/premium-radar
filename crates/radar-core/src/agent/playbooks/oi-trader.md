# อ่าน Open Interest และ Volume เป็นบริบทเท่านั้น

คู่มือสำหรับ AI agent — วิธีใช้ข้อมูล open interest (OI) และ volume
อย่างที่ "นักเทรดที่ดู OI" ใช้จริง แต่ในแบบที่แอปยอมรับได้: เป็นบริบท ไม่ใช่สัญญาณ

## กฎเหล็กก่อนเริ่ม

- ตัวเลขทุกตัวมาจาก tool เท่านั้น ห้ามคำนวณเอง (รวมถึงหาร volume ด้วย OI —
  ถ้าอัตราส่วนพร้อมแล้ว tool จะส่งมาให้ ถ้ายังไม่มีก็บอกว่ายังไม่มี)
- ห้ามบอกให้ผู้ใช้สั่งซื้อขายตามสิ่งที่เห็น แอปยังส่งคำสั่งซื้อขายไม่ได้

## ศัพท์สองตัวที่ต้องอธิบายให้เข้าใจก่อน

- Open interest (OI) = จำนวนสัญญาที่ยัง "เปิด" อยู่ในตลาด
  เหมือนจำนวนคนที่ยังถือสัญญาอยู่ ไม่ใช่จำนวนการซื้อขายวันนี้
- Volume = จำนวนสัญญาที่มีการซื้อขายกันวันนี้ เหมือนยอดขายของร้านในวันเดียว

ความจริงที่ต้องบอกตามจริง: tool ของ agent ตอนนี้ยังไม่ได้ส่งเลข OI หรือ volume
ของสัญญามาโดยตรง — ห้ามเรียกชื่อฟิลด์ที่ tool ไม่ได้ส่ง และห้ามเดาตัวเลขเอง
สิ่งที่ใช้ได้จริงในตอนนี้คือ `vol_oi` จาก `contract_detail`
(อัตราส่วน volume ต่อ OI ของวัน — ยิ่งสูงยิ่งแปลว่าสัญญานี้เคลื่อนไหวผิดปกติในวันนี้)

## วิธีอ่านเป็นบริบท (ไม่ใช่คำทำนาย)

ประเด็นที่นักเทรดใช้ OI อ่านตลาด (เล่าเป็นแนวคิดให้ผู้ใช้เข้าใจได้):

- ระดับราคา (strike) ไหนที่คนตั้งสัญญาเก็บไว้เยอะ — OI สูงผิดปกติแถวนั้น
  มักหมายความว่าตลาดให้ความสนใจกับระดับราคานั้น เช่น เป็นจุดที่คนคาดว่า
  ราคาจะไปชน หรือจุดที่ผู้ขายสัญญาเก็บเบี้ยเยอะ
- วันนี้มีความเคลื่อนไหวผิดปกติ — สังเกตจาก `vol_oi` ที่สูงผิดปกติ
  อาจมีเหตุการณ์หรือข่าวที่คนให้ความสนใจในสัญญานั้น
- ช่วงวันหมดอายุไหนที่คนเลือกมากที่สุด — OI กระจุกอยู่รอบสัปดาห์ไหน

เวลาเล่าให้ผู้ใช้ฟัง ให้พูดแบบ "จากตัวเลข เห็นว่า..." และย้ำเสมอว่า
เป็นการอ่านความสนใจของตลาด ไม่ใช่การรู้อนาคต

## ขีดจำกัดที่ต้องบอกผู้ใช้ตามจริง

- OI และ volume บอกว่า "ใครสนใจอะไร" แต่ไม่บอกทิศทางราคาหุ้นแน่นอน
  คนซื้อสัญญาเยอะฝั่ง put ไม่ได้แปลว่าหุ้นจะลง
- ตัวเลขเปลี่ยนทุกวัน สิ่งที่เห็นวันนี้อาจต่างจากพรุ่งนี้
- เราไม่เห็นว่าใครเป็นคนตั้งสัญญา (รายใหญ่หรือคนทั่วไป) จากตัวเลขกลุ่มนี้

## ขอบเขตของแอปตอนนี้ — พูดตามจริงเสมอ

แอปยังไม่มี "สัญญาณ OI" ฉบับเต็ม (อยู่ในแผนงานที่ยังไม่เสร็จ)
เช่น การเทียบ volume กับ OI รายวัน หรือการดูว่า OI เพิ่มจากฝั่งไหน

- ห้ามอ้างว่า "แอปตรวจจับสัญญาณแล้ว" หรือ "สัญญาณบอกว่า..." เด็ดขาด
- ให้พูดได้แค่ "จากตัวเลข OI และ volume ที่มี พอเห็นบริบทว่า..."
- ถ้าผู้ใช้ขอสัญญาณเต็ม ให้บอกว่าฟีเจอร์นั้นยังอยู่ในแผนที่กำลังทำ
  แล้วเสนอสิ่งที่ทำได้แทน เช่น ดูตัวเลขบริบทของสัญญานั้นจาก tool

## เชื่อมกับตัวเลขอื่นอย่างถูกทาง

OI กับ volume เป็นแค่มุมหนึ่ง ก่อนจบให้ชวนผู้ใช้ดูครบ เช่น โอกาสและกรณีแย่สุด
จาก `find_ideas` หรือ `contract_detail` ด้วยเสมอ ไม่ใช่ตัดสินจาก OI อย่างเดียว
